resource-authoring scope. No comparative generation or user study was run.

## Limits and release gate

Draft library size cannot substitute for original renders, stress states and
independent reviews. A browser inspector cannot certify native/device/game
behavior. A clean report is not an aesthetic score or accessibility certificate.
Publish rule coverage and uncertainty; validate heuristic findings with both
fault fixtures and legitimate overlaps/empty states before blocking on them.

Before claiming the expanded library improves results, execute frozen paired
builds and report failures/ties/costs. Before claiming task improvement, run
intended-user tasks and disclose sample limits. Before shipping reviewed recipes,
each needs original render/stress evidence and distinctness review. Current
research/evaluation files contain no fake comparison or human results.

## Independent source observations during implementation

The new library validator separates structural validation from aesthetic review.
Draft status and empty evidence are honest at this stage. Inspected typography
modules use the same candidate role-size ramp despite different font/context
labels; measured context-specific hierarchy and stress renders are still needed
before treating them as differentiated reviewed systems. The validator currently
requires nonempty render/evidence arrays for reviewed recipes but does not itself
establish file existence, stress coverage or independent critique. Strengthen that
gate before promoting entries. These are source observations of concurrent work,
not a complete final runtime review.

The new inspector's occlusion findings remain warnings and sparse-region findings
remain advice, which avoids claiming that intersection or blank space proves a
design defect. Labeled fixtures and accuracy accounting remain necessary before
stronger claims. No detector accuracy statistics were generated in this review.

## Builder integration and runtime verification

The builder subsequently differentiated the six candidate typography role ramps
for dense data, display, editorial, long reading, multiscript and general UI.
Metrics and actual language behavior still require target-runtime review.
Review promotion now rejects missing/unsafe examples, absent normal/stress
states, incomplete evidence metadata and validated status without task-study
records. These checks validate structure, not the truth of a submitted study.

Six unit/library tests and nine Chromium tests passed. The specimen suite
captured 108 cases: 36 screens each at 320×568 normal, 390×844 interrupted and
1440×900 normal. Seventy-two normal/interrupted renders are packaged with the
skill. The suite checks bounded DOM errors and selected catalog, dialog, booking,
message and timer interactions. It does not establish native behavior or all-flow
coverage. See `skills/design-to-product/evals/specimen-review.json` for the
portable case summary.

The first specimen run exposed a contrast false positive where chart labels lay
outside a painted ancestor. The builder changed that case to unverified and
added a real-browser counterexample fixture. The final run had no measured errors
in the checked specimen cases; warnings/advice remain manual review candidates.

Builder screenshot inspection covered the catalog at 1440/390 and selected
marketing, mobile capture, desktop editor, dashboard interruption and game HUD
renders. These showed readable hierarchy and task-specific structure. Remaining
craft limitations include repeated specimen chrome, sparse original illustration,
and a mobile bottom bar that overlays the scrolling content at the viewport edge;
these studies do not demonstrate the full range of imagery or native input.
No independent comparative craft scores were assigned.

The independent reviewers completed source feedback and implementation tests.
Their follow-up screenshot review could not complete because delegated turns
hit an account usage limit. This limitation does not invalidate completed tests,
but it prevents calling the pilot independently visually reviewed.


## Follow-up control and responsive review

The user identified native dropdown popup mismatch, truncated selected values,
cramped intermediate layouts, noisy repeated copy, redundant visible close labels
and dialog scroll chaining. The catalog was simplified and its filters reflow
before their labels become cramped. Reusable study controls now include a themed
select-only combobox (native value/no-JS fallback), full wrapping labels, keyboard
navigation/typeahead/cancellation and viewport-bounded popup placement. Native
required controls keep validation behavior. Icon close actions have accessible
names and hover/pressed/focus feedback. Modal open/close preserves document scroll
position/styles and contains wheel propagation.

Two added real-Chromium tests cover eight widths (320, 390, 540, 700, 768, 960,
1024, 1440), dropdown bounds/labels, keyboard selection/cancel, close hover and
wheel scrolling at the end of a modal. Six unit/library plus eleven browser tests
passed after integration. Builder inspected final phone/tablet/catalog/dialog
screenshots. These checks do not establish screen-reader or native-device support.
